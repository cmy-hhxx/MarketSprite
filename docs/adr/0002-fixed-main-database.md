# ADR-0002：固定主数据库与内部结构代数

- 状态：已接受
- 日期：2026-08-13

## 背景

早期实现把结构代际编码进主文件名。文件名因此暴露历史迁移链，用户也容易把内部结构误认为产品版本或数据版本；每次调整结构都要更换文件名，还会在 Application Support 根目录留下多个候选库。

同时，旧 schema 把行情设计成永久历史档案：已移除标的的行情继续残留，约束大量只在 Swift 中存在，SQLite 本身允许非法状态。而当前产品只消费每个标的的最新行情。

## 决策

### 固定主文件与身份

- 主数据库永远是 `~/Library/Application Support/MarketSprite/marketsprite.sqlite`。
- 文件名只代表"MarketSprite 唯一权威数据库"，不代表产品版本或结构代数。
- `PRAGMA application_id = 0x4D535052`（ASCII `MSPR`）证明这是 MarketSprite 数据库。
- `PRAGMA user_version` 只表示内部结构代数，不展示给用户，也不进入主文件名。
- 带时间戳的备份文件可以存在于 `Backups/`，但主文件名永不改变。

### 数据边界

| 语义 | 存储 |
| --- | --- |
| 当前观察列表、提醒规则、最新行情缓存 | `marketsprite.sqlite`（五张 STRICT 表） |
| 外观、窗口、刷新频率、声音、快捷键 | UserDefaults |
| 刷新任务、提醒布防状态、UI 状态 | 内存 |

用户数据是权威事实；行情只是可删除、可重建的最新缓存。删除观察标的等于结束关注关系，其目标价和行情缓存必须级联删除。每个观察标的永远只保留最新一个交易日：新交易日替换旧 `quote_cache`，分钟线由外键级联删除。

### 升级路径

- 固定主库不存在时，只把指定的旧版主数据库视为一次性迁移源；其他旧数据库、早期行情库和人工备份不参与数据选择。
- 迁移在临时数据库内完成并验证，成功后才原子重命名为 `marketsprite.sqlite`；任一步失败都保留迁移源不动，绝不创建空主库冒充成功。
- 固定主库已存在时始终以它为准，不读取任何旧库。主库建立并验证成功后，再把根目录内识别到的旧数据库、早期行情库、人工备份和边车文件独立归档到 `Backups/legacy-<UTC时间>/`；归档不依赖本次启动是否执行过迁移。
- 未来结构升级只操作固定的 `marketsprite.sqlite`：升级前用 SQLite backup API 创建 `Backups/pre-upgrade-<UTC时间>.sqlite`，然后在事务内按内部结构代数单向升级。
- `Backups/` 永不作为数据源被自动扫描或打开；正常读写路径只理解当前结构。

### 不保留兼容读写路径

- 不存在旧字段 fallback、旧查询、双写或降级读写。
- 如果用户安装更旧的应用版本，旧版本拒绝新结构是预期行为，不提供降级兼容。
- "不保留向后兼容"重新精确为：允许原子、单向的数据升级，但升级后的正常代码只支持当前 schema。

## 结果

- Application Support 根目录永远只有一个活动数据库 `marketsprite.sqlite`；旧文件只存在于 `Backups/`。
- 启动时校验 `application_id`、结构代数、`PRAGMA quick_check` 和外键一致性；失败阻断启动，不创建内存数据库，也不静默重建。
